OPLOSSING VOOR STACKOVERFLOWERROR BIJ ZOEKBALK
==============================================

Probleem
--------

De applicatie crasht met:

StackOverflowError

De stacktrace wijst naar:

- TrajectorySelectionController.java regel 45
- TrajectorySelectionController.java regel 85

De oorzaak zit in deze combinatie:

routeBox.getEditor().textProperty().addListener((observable, oldValue, newValue) -> filterRoutes(newValue));

en:

routeBox.setItems(FXCollections.observableArrayList(filteredRoutes));


Wat gebeurt er?
---------------

1. De ComboBox is editable gemaakt met routeBox.setEditable(true).
2. JavaFX zet tekst in de editor van de ComboBox.
3. Die tekstwijziging triggert de listener.
4. De listener roept filterRoutes() aan.
5. filterRoutes() vervangt de items met routeBox.setItems(...).
6. JavaFX werkt intern de selectie en display opnieuw bij.
7. Daardoor verandert de editor-tekst opnieuw.
8. De listener wordt opnieuw getriggerd.
9. Dit blijft doorgaan tot Java een StackOverflowError geeft.


Wat zou ik herstellen?
---------------------

Ik zou de zoekfunctie anders opzetten zodat tekst wijzigen en items vervangen elkaar niet eindeloos blijven triggeren.

Concreet:

1. In TrajectorySelectionController een guard-boolean toevoegen:

   private boolean updatingRouteBox;

2. In de listener op routeBox.getEditor().textProperty() eerst checken of we al intern aan het updaten zijn.

3. In filterRoutes() rond routeBox.setItems(...) tijdelijk updatingRouteBox = true zetten.

4. Na het vervangen van de items de getypte tekst terugzetten in de editor, zodat JavaFX niet zelf de editor overschrijft met geselecteerde route-tekst.

5. Geen route automatisch selecteren tijdens typen, want dat verandert opnieuw de editor-tekst.

6. refreshTimes() alleen aanroepen wanneer de gebruiker echt een route selecteert, niet bij elke zoektekstwijziging.

7. broncode_uitleg.txt daarna bijwerken zodat die de nieuwe zoekbalk/filterlogica correct beschrijft.


Voorbeeld van de kernoplossing
------------------------------

private boolean updatingRouteBox;

private void filterRoutes(String searchText) {
    if (updatingRouteBox) {
        return;
    }

    updatingRouteBox = true;
    try {
        String typedText = searchText == null ? "" : searchText;
        String search = typedText.toLowerCase().trim();

        var filteredRoutes = allRoutes.stream()
                .filter(route ->
                        route.getDeparture().toLowerCase().contains(search)
                                || route.getArrival().toLowerCase().contains(search)
                                || route.toString().toLowerCase().contains(search)
                )
                .toList();

        routeBox.setItems(FXCollections.observableArrayList(filteredRoutes));
        routeBox.getEditor().setText(typedText);
        routeBox.getEditor().positionCaret(typedText.length());

        if (filteredRoutes.isEmpty()) {
            timesList.setItems(FXCollections.observableArrayList());
            infoLabel.setText("Geen route gevonden.");
        } else {
            infoLabel.setText("");
        }
    } finally {
        updatingRouteBox = false;
    }
}


Extra verbetering
----------------

Deze regel is risicovol:

routeBox.setOnAction(e -> refreshTimes());

Bij een editable ComboBox kan onAction ook door editoracties afgaan.

Beter is luisteren naar valueProperty:

routeBox.valueProperty().addListener((observable, oldValue, newValue) -> {
    if (newValue != null) {
        refreshTimes();
    }
});

Dan wordt refreshTimes() alleen uitgevoerd wanneer er echt een route geselecteerd is.


Samenvatting
------------

De crash komt niet door FXML en niet door Maven.

De crash komt door een eindeloze feedbackloop:

tekstwijziging -> filterRoutes() -> routeBox.setItems() -> JavaFX wijzigt editor-tekst -> tekstwijziging -> filterRoutes()

De oplossing is:

- feedbackloop blokkeren met een guard-boolean;
- zoeken en route-selectie van elkaar scheiden;
- tijden alleen verversen bij een echte routekeuze;
- daarna broncode_uitleg.txt bijwerken.
